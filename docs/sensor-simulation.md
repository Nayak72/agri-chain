# AgriChain Sensor Simulation

## Overview

The cold-chain monitoring system uses simulated temperature and humidity readings. No physical IoT devices or sensors are connected.

## Simulation Architecture

```
User → Frontend → FastAPI Endpoint → SensorSimulatorManager → MongoDB
                                                ↓
                                        Deterministic Scenario Engine
                                                ↓
                                        Sensor Reading (SIMULATED)
```

## Sensor Session

Each simulation session contains:
- Session ID
- Shipment ID
- Scenario (see below)
- Interval (seconds)
- Status (RUNNING, PAUSED, STOPPED)
- Reading count
- Created by

## Sensor Reading

Each reading contains:
- Reading ID
- Session ID
- Shipment ID
- Simulated device ID
- Temperature (°C)
- Humidity (%)
- Timestamp (UTC)
- Source: "SIMULATOR"
- Is simulated: true
- Configured temperature range
- Configured humidity range
- Status (NORMAL, WARNING, CRITICAL)

## Simulation Scenarios

| Scenario | Description | Behavior |
|----------|-------------|----------|
| Normal Conditions | Stable readings within range | Temp/humidity fluctuate ±0.5°C / ±2% |
| Temperature Excursion | Temperature exceeds max | Temp rises 3-8°C above max |
| Humidity Excursion | Humidity exceeds max | Humidity rises 5-15% above max |
| Both Excursion | Both temp and humidity exceed | Both parameters exceed thresholds |
| Fluctuation | Repeated temperature changes | Sinusoidal temperature variation |
| Recovery After Alert | Returns to normal after alert | Gradual return to baseline over 5 minutes |

## Simulation Controls

- Start simulation
- Pause simulation
- Resume simulation
- Stop simulation
- Reset simulation
- Generate next reading manually
- Select scenario
- Configure reading interval

## Alert Generation

Alerts are created when readings violate configured handling profiles:

| Severity | Condition |
|----------|-----------|
| INFO | Reading within normal range |
| WARNING | Reading slightly outside range |
| CRITICAL | Reading significantly outside range |

Alerts include:
- Alert ID
- Shipment ID
- Reading reference
- Alert type (temperature/humidity)
- Severity
- Observed value
- Configured allowed range
- Duration
- Acknowledgement status
- Corrective action
- Resolution status

## Key Design Decisions

1. **Backend generation**: All sensor values generated by FastAPI backend, not frontend
2. **Deterministic scenarios**: Same scenario produces consistent results for demos
3. **Singleton per shipment**: Prevents duplicate simulator tasks for same shipment
4. **SIMULATED DATA labels**: All UI readings prominently labeled as simulated
5. **MongoDB persistence**: Readings and alerts stored in database
6. **Ledger integration**: Significant alerts create ledger entries

## Important Notice

All temperature and humidity values are **simulated for demonstration purposes**. They do not represent real hardware measurements and should not be used for actual cold-chain compliance decisions.
